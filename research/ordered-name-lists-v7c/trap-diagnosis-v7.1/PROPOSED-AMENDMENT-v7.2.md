# Proposed v7.2 — supplementary context-role null and complete trap qualification

STATUS: DRAFT FOR RE'S APPROVAL. NOT ACTIVE. Written25October2026 after a declared diagnostic of v7.1 attempt2.

## Evidence and purpose

The original C3 algorithm followed v7's global value-frequency rule. In this trap, however, inactive whole-word base entries mostly hold x, while active character fallback entries hold26different letters. Global permutation moves those x values into the active fallback. The memorized word mappings contribute no excess at all; five fallback coincidences in each reading produce the corrected PARTIAL. This is evidence about the baseline's scope, not an invalidation of its arithmetic and not a decipherment.

A predeclared, separately labelled sensitivity preserves the two default-use roles. The E1 tails change from1/1001 in each reading to65/1001(H) and84/1001(F). These exposed diagnostic outcomes motivate this proposal; they are not new held-out validation. Attempt1 and attempt2 stay unchanged and NOT QUALIFIED.

## Changes proposed

1. **Keep original C3. Add a supplementary C3-R bank.** It has at least1000equal-complexity keys. Derive each unit's role only from its declared KEY context-condition slots, before any scoring. Permute base values within identical role signatures. Permute rule values within identical role-and-condition signatures. Preserve the original map/rule value multisets globally and within strata, all unit identities, condition assignments, context slots and K. Neither unit names, decoded values, held source forms nor desired results define strata. Record bank hashes and actual distinct-key counts.
2. **Use both banks for admission.** A PASS must satisfy v7.1's coherence and matched-control gates separately under original C3 and C3-R, with at least TWO of the SAME E1–E5 reaching the99th-percentile criterion in BOTH banks. A non-PASS is PARTIAL only when at least ONE of the SAME evaluations reaches the99.8th-percentile criterion in BOTH banks; equivalently use max(p_original,p_role) for each evaluation. Otherwise it is FAIL. This is a stronger composite comparison, not a replacement or deletion of the original bank. Both readings remain required.
3. **C1b operates on registered raw source glyphs before fixed tokenization.** Re-tokenize the shuffled source with the unchanged KEY tokenizer. Validate source/tokenizer agreement, original unit inventories, word geometry, fixed endpoint classes, unknown barriers and immutable source/key hashes. Whole-word tokenizers may not bypass glyph shuffling by presenting one opaque unit.
4. **Actual-trap qualification must have finite E3/E4.** Before fitting a trap, freeze a qualification cohort of whole source lines jointly readable in H/F, using native source uncertainty only. Keep the same preregistered training/held page split and original line order; take the first40eligible lines per partition, or report insufficient support. No key-dependent deletion or fallback repair. Preserve all excluded lines/unknown slots in a coverage ledger. The literal trap requirement remains FAIL in both readings, now also requiring finite E3/E4 and complete matched controls. This limited qualification does not certify loss treatment on native-uncertain whole corpora.
