# A complete inventory of written forms

> Plain-English reading guide to the archived snapshot. The linked reports contain the full rules, results, and qualifications. This guide is editorial material added after the original archive.

## What we tested

Built a searchable inventory of characters, proposed sign groups, word parts, sequences, and complete words across the available transcriptions.

## What we found

The atlas exposes rare forms as well as frequent ones, with filters for section, hand, layout, page, and position. Unknown slots and incomplete spatial mapping remain explicit.

## What remains unresolved

Alternate transcriptions describe the same manuscript rather than independent texts. Written units in this atlas are not established syllables, grammatical categories, or meanings.

## What is in this folder

- [SOURCE-MANIFEST.json](SOURCE-MANIFEST.json): source attribution, access history, or rights context.
- [VERIFICATION.json](VERIFICATION.json): checks or qualification evidence; read the scope of the gate.
- [report.html](report.html): explanation, outcome, or dated checkpoint.
- [ROWS.json.gz](ROWS.json.gz): saved data or supporting evidence; field definitions come from the protocol/report.
- [SHA256SUMS.json](SHA256SUMS.json): saved data or supporting evidence; field definitions come from the protocol/report.
- [app.js](app.js): implementation or checking code.
- [build.py](build.py): implementation or checking code.
- [data.js.gz](data.js.gz): saved data or supporting evidence; field definitions come from the protocol/report.

File formats: JSON stores structured values or settings; JSONL stores one event/trial record per line; CSV/TSV stores tables. Python and JavaScript files are code. Compressed `.gz`/`.xz` files retain the original bytes; the repository restoration helper can unpack them. HTML reports may require a local browser rather than GitHub’s file viewer.
