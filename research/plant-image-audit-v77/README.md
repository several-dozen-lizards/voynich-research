# Checking the evidence behind plant identifications

> Plain-English reading guide to the archived snapshot. The linked reports contain the full rules, results, and qualifications. This guide is editorial material added after the original archive.

## What we tested

Revisited six plant images and the provenance of proposed botanical and historical-name matches.

## What we found

Some visual candidates remained useful, but no species was confirmed. Several apparently convenient historical name anchors were less secure than spelling resemblance suggested, and alternate identifications were retained.

## What remains unresolved

Overview images and edited notebook transcriptions do not settle fine botanical details or autograph readings. The plant-to-name-to-word chain remained unqualified.

## What is in this folder

- [FREEZE.json](FREEZE.json): the rules, intended scope, or pinned setup.
- [SOURCES.json](SOURCES.json): source attribution, access history, or rights context.
- [VERIFICATION.json](VERIFICATION.json): checks or qualification evidence; read the scope of the gate.
- [report.html](report.html): explanation, outcome, or dated checkpoint.
- [AUDIT.json](AUDIT.json): checks or qualification evidence; read the scope of the gate.
- [H-F-SLOTS.json](H-F-SLOTS.json): saved data or supporting evidence; field definitions come from the protocol/report.
- [LIMITS.json](LIMITS.json): saved data or supporting evidence; field definitions come from the protocol/report.
- [build.py](build.py): implementation or checking code.

File formats: JSON stores structured values or settings; JSONL stores one event/trial record per line; CSV/TSV stores tables. Python and JavaScript files are code. Compressed `.gz`/`.xz` files retain the original bytes; the repository restoration helper can unpack them. HTML reports may require a local browser rather than GitHub’s file viewer.
